# 鱼竿钓走 GIF

用户通常只发视频。默认自行审片选段，用下一款鱼竿钓走主要主体，交付 **50fps GIF + 60fps 无声 MP4**。不需要先问选哪款、剪哪段或要不要继续。具体要求优先；同一视频的重做和修改保留原款。

## 开始

`SKILL` 为本文件所在文件夹，入口为 `scripts/fishing_gif.py`，Python 3.10+。先运行 `doctor`；缺依赖时，在本技能的 `.venv` 中安装 `requirements.txt`，后续使用该虚拟环境的Python。FFmpeg来自PATH或依赖内的二进制，不依赖另一技能、本机用户名或 API Key。Windows用实际Python路径调用同一脚本，无需Bash。

命令见 [制作步骤](references/workflow.md)，写配置时看 [配置说明](references/project-config.md)。

## 制作

1. **审片选段。** 用 `inspect` 生成覆盖全片的时间线并实际查看；复杂动作增加抽帧或播放。选约2～4秒、动作易懂、最后主体完整可见的一段。优先无遮挡、背景可恢复、接触关系明确的时机。剪好的短视频可整段使用。
2. **准备项目。** 用 `prepare`，默认 `--variant auto`，新项目用新目录。它按原视频SHA256保留选款，输出60fps片段、拾取帧及 `project.json`。轮换由脚本持久保存，不凭聊天记忆选款。
3. **抠主体。** 查看拾取帧，填写轮廓或遮罩、真实挂点，运行 `matte`，查看棋盘格检查图。包括应被带走的附属物，排除地面、阴影和应留下的物体。灰腿不能误删，灯眼不能因颜色过滤丢失。旧样片的过滤色、坐标不能直接复制到新素材。
4. **补背景。** 先查看拾取帧，用内置图像生成工具仅移除主体及其投影，保留人物、鞋、家具和镜头；保存到 `cleanup.plate` 并核对构图。已有干净背景可复用。图像生成能力不可用时说明缺少哪项能力，保留准备结果，不声称已完成、不索要API Key，不交付有主体残影的版本。
5. **编排预览。** 使用包内完整鱼竿PNG，调整位置、比例、角度，让手可辨、挂饰醒目、主体动作清楚。保持已确认的大号比例。线落到真实挂点，绷紧后离地，连续上升摆动并出画，不在半空停顿。`preview` 输出关键帧和出画检查；鱼线与钩由脚本绘制。
6. **渲染交付。** `render` 分别计算60fps与50fps母版，不能靠重复帧伪造高帧率。实际查看导出GIF/视频，检查拾取接缝、完整出画、地面补片和手的大小。修订渲染到新版本。通过后运行 `complete --qa-notes "实际检查内容"`，向用户展示GIF并链接MP4；仅 `complete` 推进轮换，失败、重试和修改不会重复推进。

## 固定资产与轮换

**关注加号 → 点赞红心 → 收藏五角星 → 转发弯曲右箭头 → 循环**。

- `assets/rods/` 内是四张完整透明图，不必重新生成、拆层。参考画布1254×1254，竿尖约(103,166)，握柄支点约(900,930)。
- 转发箭头必须向右。不能直接镜像整图导致符号反向；调整位置和角度，确有需求再另制素材。
- 状态位于 `$CODEX_HOME/fishing-gif/rotation.sqlite3`，未设置时为 `~/.codex/fishing-gif/`。各同事独立轮换，状态不随ZIP分发。测试必须指定独立 `--state-dir`，不消耗正式轮换。
- 用户明确选款用 `--variant follow|like|save|share`，不推进自动轮换。

## 验收边界

脚本负责可重复渲染和格式验证；选段、挂点、抠像、干净背景和视觉验收由Codex根据本期素材完成。提起阶段用拾取帧的原像素做位移与摆动，是合成动画，不是逐帧视频生成。主体严重遮挡、裁出画面或相机剧烈运动时换合适片段，不把旧样片坐标当通用算法。检测到HDR先做并核对SDR转换。
